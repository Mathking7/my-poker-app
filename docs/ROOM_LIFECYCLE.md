# 房间生命周期与历史记录

本项目是 Vercel 静态前端 + Firebase Firestore，没有常驻应用服务器。因此房间维护采用“客户端协作维护”的方式：玩家进入大厅或房间时，会顺手刷新房间状态、公开索引和必要的历史记录。

## 数据分层

- `rooms`：完整房间数据，包含牌桌状态、玩家、日志、结算和结构化牌局历史。
- `publicRoomIndex`：公开大厅索引，只保存公开房间的最小展示信息。私密房间不会写入这里。
- `users/{uid}/roomHistory`：个人最近房间记录。玩家进入过公开或私密房间后，会在自己的历史里看到该房间。

## 保留策略

- 公开房间：有人在线时展示在公开列表；空置后从公开列表移除，保留 30 分钟，之后自动清理。
- 私密房间：不展示在公开列表；创建时可选择空置后保留 1 小时、24 小时、7 天或 30 天。
- 最近房间：既是个人入口，也是轻量牌局历史索引。房间过期或被解散后记录会显示为不可加入，但最近几局摘要会保留到个人历史过期。

## 维护触发点

- 大厅加载和刷新公开房间时，会扫描公开索引并校验真实房间。
- 大厅空闲时会周期性清理过期房间，并补齐旧房间的生命周期字段。
- 房间内玩家心跳会刷新 `lastHumanActiveAt`，并把房间从空置状态恢复为活跃状态。
- 创建、加入或申请加入房间时，会写入个人最近房间记录。

## 牌局历史

每局开始时记录座位、初始筹码和盲注；玩家行动时记录轮次、行动类型、投入额、目标下注额和行动后底池；结算时写入本局公共牌、分池、赢家、亮牌信息和行动列表。抽屉中的“牌局历史”直接读取这些结构化数据。

个人最近房间会保存精简后的最近牌局记录，用于房间已删除时继续查看个人历史。因为当前没有服务器，客户端无法在解散房间时主动遍历并删除所有用户的个人历史；这些记录会在用户下次打开最近房间时自检，超过保留期或没有牌局内容的陈旧记录会自动清理。

个人历史中的底牌采用“公共历史 + 私有补充”的方式保存：`rooms/{roomId}.handHistory` 只记录公共牌、行动、赢家和公开亮牌；`users/{uid}/roomHistory/{roomId}.recentHands` 会在结算时额外保存该用户自己的 `heroCards`，并在后续刷新时保留这份私有记录。因此最近房间里可以回看自己的底牌，但不会把未公开底牌显示给其他玩家。需要注意的是，在无服务器架构下，当前房间文档仍会短暂包含正在对局玩家的 `players[].hand`，这不是严格防作弊模型；若未来需要完全防止客户端读取他人底牌，应迁移到服务端发牌或按玩家拆分私有手牌文档。

个人历史记录带有 `historySchemaVersion`，当前版本为 1。房间内牌局历史抽屉会订阅当前用户的个人历史，把自己的 `heroCards` 合并到公共牌谱展示中；其它玩家仍只能看到公开亮牌。

## 后续维护建议

- 如果以后加入 Cloud Functions，可把过期清理和索引刷新迁移到服务器定时任务。
- 如果开启 Firestore TTL，可以将 `ttlAt` 配置为自动删除字段，客户端维护继续作为 UI 和兼容兜底。
- 如果房间量显著上升，公开列表可在 `publicRoomIndex` 上增加 `gameType`、`updatedAt` 查询索引。
